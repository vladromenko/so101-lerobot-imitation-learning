# so101_box_extraction — достать кубик из коробки (обзорная камера + SAM 3)

Папка `~/Projects/so101_box_extraction` на homebrain. Файлы существующего проекта
`so101_autonomous_pick_place` не изменены: код только импортирует его (планировщик, адаптер драйвера, TaskArm,
API сервера со SAM 3). Складывание кубиков в коробку остаётся за существующим кодом проекта.

## Запуск

Интерфейс с Mac: **http://homebrain.local:8030** (запуск `./ui.sh`, остановка `./ui.sh stop`). Две вкладки:
«Работа» (кнопки «Сложить все кубики в коробку» и «Вытащить все кубики из коробки», камера, журнал, STOP) и «Как это считается»
(учебник на настоящей 3D-модели руки, как в LeLab: живая рука с графиками суставов и скорости, системы координат (основание, звенья,
кончик, камера, стол, коробка, кубик), матрицы поворота $M_x, M_y, M_z$ и оси суставов на руке, прямая кинематика по шагам, обратная
кинематика (треугольник, поправка Ньютона), камера→стол, захват, гравитация, столкновения (зазор каждого звена), поиск пути RRT-Connect и
сглаживание, последний реальный план с ползунком по фазам).

То же из терминала:
```bash
cd ~/Projects/so101_box_extraction
./run.sh --mode stow    --execute --confirm-attended      # все кубики со стола — в коробку (ставит на дно, не бросает)
./run.sh --mode extract --execute --confirm-attended      # все кубики из коробки — на стол
./run.sh --mode stow                                       # без --execute: измерить, спланировать, просимулировать
./run.sh --mode extract --execute --confirm-attended --max-cubes 1
```
Остановка: кнопка STOP, Ctrl+C или STOP штатного интерфейса (рука удерживает позу).
Количество кубиков не задаётся: цели берутся по очереди; остальные кубики — препятствия. Кубик, который нельзя измерить как ровный
(лежит наклонно у стенки), остаётся препятствием и не берётся.

Скорость: `BoxArmDriver.speed_scale = 1.5` и множители по фазам `BoxArmDriver.PHASE_SCALE` (подход, раскрытие и перенос ×2, отвод ×1,6,
вход, подъём и опускание ×1,4; точные фазы у кубика остаются медленными). Одно движение по всей цепочке точек идёт единым профилем
«минимального рывка». После поиска RRT-Connect путь сглаживается кубическим сплайном (`TunedExtractionPlanner.transport/_smooth`);
каждая точка сплайна заново проверяется на столкновения, при провале остаётся исходная ломаная. Запас на отставание руки (3° на суставе)
рассчитан на эти скорости.

Складывание в коробку: площадки на дне выбираются по длинной оси проёма (`box_extract/stow.py`); когда дно заполнено, программа пишет
«в коробке больше нет свободного места» и останавливается без ошибки (ёмкость примерно 2–3 кубика).

Кубик, который в коробке нельзя взять там, где он лежит (`box_extract/nudge.py`): если ни для одного кубика нет входа захвата,
программа ищет на сетке 1 см (в осях коробки, грани вдоль стенок) ближайшие места, где вход есть, и пробует подвинуть кубик туда
закрытыми губками (подход сверху, спуск рядом, толчок по полу, отход). План проверяется так же, как извлечение (сетки деталей, команда с
компенсацией гравитации, отставание суставов, симуляция всего прогона); после толчка сцена измеряется заново (до 5 толчков на кубик).
Если ни один толчок невозможен, программа за ~4 минуты пишет причину и останавливается. Для коробки у края зоны досягаемости это частый
случай: чтобы подвинуть кубик к основанию, толкатель должен встать дальше кубика, а там рука не достаёт или мешает стенка коробки.
Карта «где в коробке вообще возможен захват»: `tests/reach_map.py`; проверка толчка: `tests/push_probe.py`, `tests/push_sim_probe.py`.

Только камера на руке: пока не поддерживается. Проектная калибровка запястной камеры не проходит проверку (проекция даёт ошибку
20–35 px), а красный крест виден только обзорной камере. Реалистичный путь — ArUco-метка на столе (`vision/fiducials.py`) для
калибровки запястной камеры; пока не сделан.

## Что делает один цикл

1. 3 скана SAM 3 обзорной камерой → метрическая сцена: проём коробки на уровне кромки, клапаны/крышка,
   кубики, свободные площадки на столе. Проём сервер иногда не находит (откинутая крышка сливается с коробкой):
   тогда он строится по рёбрам бортов (`box_extract/opening_fallback.py`, сглаживание по последним сканам).
2. План: грасп по граням кубика, вертикальный подъём выше кромки, перенос RRT-Connect, мягкая постановка.
   Отступ неподвижной губки считается по реальному сдвигу команды от компенсации гравитации драйвера,
   все команды проверяются заранее (`box_extract/planning.py`).
3. Полный прогон на симуляторе драйвера: раскладка из сложенного положения, все фазы, перепланирование
   после схвата, парковка. Любое пересечение со стенками/кубиками — отказ до включения моторов.
4. Свежий скан должен совпасть с планом (≤4 мм) → только потом включение моторов.
5. Перед каждой фазой — новый скан (коробка не сдвинута, соседи на месте, нового кубика нет).
6. После — скан подтверждает, что кубик на столе и вне коробки.

## Состояние проверки

Реальный цикл от начала до конца пройден (запуск `./run.sh --execute --confirm-attended`, оператор у STOP): измерение, план,
симуляция, раскладка из сложенного положения, подход, вход в коробку, захват, подъём над кромкой, перенос, постановка на стол,
отвод, парковка, скан-подтверждение (ошибка постановки 4,7 мм), «коробка пуста». Кубик лежал у борта коробки, крышка откинута.
Один кубик в коробке; несколько кубиков и другие раскладки реально не прогонялись (в симуляторе планируются).

Что программа делает сама, без остановки на оператора:
- проём коробки по рёбрам бортов, когда сервер его не находит (откинутая крышка);
- сдвинутую коробку: путь смещается вместе с ней (до ~24 мм), больше — пересчёт; рука над коробкой закрывает борт — тогда
  положение не перемеряется, но и не останавливает работу;
- сцена изменилась до первого рабочего хода, или губки сомкнулись впустую, или кубик сдвинули: разжимает губки, выходит по
  пройденному пути, заново измеряет и планирует (до 4 раз подряд);
- неизмеримый предмет вдали от коробки (обрезан краем кадра): остаётся препятствием;
- нет пути с широкими запасами: сужает запасы вокруг клапанов и стенок по лестнице (24→5 мм), симуляция с настоящими
  размерами всё равно должна пройти.

Если защита всё же остановила программу, рука держит позу. Вернуть: `scripts/retreat.py --plan <лог>/cycle-N/plan.json
--phase approach,enter [--open-gripper]` (с кубиком в захвате сначала `--phase extract_vertical,transfer --keep-path-gripper`
по `plan-after-grasp.json`).

## Калибровка обзорной камеры по красному кресту

Штатная «живая» сверка обзорной камеры с рукой (крестик на подвижной губке против кинематики) требует ≤5 px; калибровка ушла на ~5 px.
`scripts/recalibrate_overview.py --observations <logs/overview_hand_eye/.../observations.json> --install` пересчитывает камеру по
наблюдениям крестика (их собирает штатный `calibrate_overview_hand_eye.py --execute --marker-seed X Y`) с теми же нулями суставов, проверяет
на позе, которой подгонка не видела, и только при улучшении ставит новую калибровку, сохранив старую как `config/calibration.old-auto-*.json`.
Сервер проекта читает калибровку при старте: после установки его нужно перезапустить один раз.

## Камера на руке

Режима «только камера на руке» пока нет. Для метрической работы ей нужна калибровка крепления; штатная в проекте
не установлена. `scripts/calibrate_wrist.sh` собирает ракурсы (адаптируются к положению кубика и держатся
подальше от коробки) и пытается подогнать крепление; на сценах с печатными кубиками (SAM даёт только цветную
верхнюю грань) подгонка пока не проходит пороги проекта, поэтому ничего не устанавливается.

## Физические пределы

Захват SO-101 с раскрытыми губками ≈86 мм вдоль оси схвата и ≈52 мм поперёк. Нужен проём больше этого с запасом
(для текущей коробки 15×19 см этого хватает). Если захват невозможен, программа останавливается до движения и
пишет причину (`NO EXTRACTION POSSIBLE`).

## Тесты без моторов

`tests/` — офлайн-пробы на сохранённых сканах и на живом сервере: сцена, кандидаты захвата, полный прогон на
симуляторе (`offline_real_probe.py`), устойчивость проёма (`opening_stability.py`), сдвиг команды (`diag_command_shift.py`).
