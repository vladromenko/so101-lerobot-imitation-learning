# SO-101 AUTONOMOUS MANIPULATION LAB
## Полная реализация автономной роботизированной системы с wrist-камерой, геометрическим захватом и библиотекой экспериментов

# 1. ГЛАВНАЯ ЗАДАЧА

Ты работаешь непосредственно с моим существующим проектом LeRobot SO-101 на Jetson 16 GB.

Твоя задача — разработать новую, быструю, чистую и автономную систему манипуляции предметами.

**Я хочу нажимать на экране на предмет, который видит камера, выбирать действие, после чего робот должен самостоятельно определить, как лучше захватить предмет, выполнить движение и проверить результат.**

Основной сенсор для точного управления — камера на запястье SO-101 (wrist-camera).

Верхняя камера используется для общего обзора сцены и вспомогательной локализации.

Робот должен самостоятельно выполнять:

1. Захват предметов.
2. Укладку кубиков в коробку.
3. Извлечение кубиков из коробки.
4. Сортировку кубиков по цветам.
5. Построение башни из кубиков.
6. Разбор башни.
7. Размещение кубиков рядами и по шаблону.
8. Компактную укладку в коробку.
9. Перестановку мешающих предметов.
10. Автоматическое восстановление после неудачного действия.
11. Подготовку сцены для следующего эксперимента.
12. Последовательное выполнение нескольких экспериментов.
13. Выбор произвольного поддерживаемого предмета нажатием на изображение.
14. Перемещение выбранного предмета в коробку или безопасную зону передачи человеку.

**Все действия должны выполняться локальным Python-кодом. Никакого ChatGPT, Codex, LLM или MCP во время выполнения эксперимента.**

Главная идея архитектуры:

**Одна универсальная операция захвата и перемещения, используемая всеми экспериментами.**

Не создавай отдельные реализации кинематики и управления рукой для сортировки, башни или укладки.

# 2. ОСНОВНЫЕ ТРЕБОВАНИЯ

## 2.1. Быстрота

После нажатия Start робот должен сразу начать выполнение задачи из состояния Ready.

Не допускаются многоминутные программные задержки перед обычным захватом.

Камеры, драйверы, модели и калибровки загружаются заранее.

Измеряй задержку между нажатием Start и первой командой приводам. Устраняй подтверждённые программные задержки.

Не устанавливай искусственное ограничение вроде 20 секунд на всю задачу. Оптимизируй реальное время при сохранении точности и безопасности.

## 2.2. Автономность

Робот самостоятельно:

- Определяет предметы.
- Рассчитывает координаты и размеры.
- Выбирает допустимый захват.
- Определяет свободное пространство.
- Рассчитывает IK.
- Планирует траекторию.
- Наводит захват по камере.
- Выполняет перемещение.
- Проверяет результат.
- Исправляет штатные ошибки.
- Переходит к следующему предмету.

Никакого ручного подбора координат под отдельный кубик.

## 2.3. Чистота кода

- Python.
- Небольшие понятные функции.
- Минимальное количество классов.
- Минимальная вложенность.
- Никакого дублирования.
- Никаких ненужных менеджеров и абстракций.
- Никаких бессмысленных обёрток.
- Никаких лишних процессов.
- Никаких бесконечных повторов.
- Никаких случайных компенсационных смещений.
- Не использовать `continue`.
- Использовать существующие работающие библиотеки и драйверы.

Не добавляй новую архитектуру ради самой архитектуры.

## 2.4. Только необходимая разработка

Не создавай:

- Папку `docs/`.
- Отдельную инфраструктуру тестирования.
- Виртуальные симуляции.

- Ненужные Docker-сервисы.
- Огромные отчёты.
- Дополнительные AI-агенты.

Не запускай MuJoCo перед каждым физическим действием.

При этом сохраняй необходимые встроенные проверки геометрии, достижимости, столкновений и безопасности. Новые движения сначала проверяй без контакта, затем выполняй под наблюдением человека с доступным STOP.

**Главный результат — реально работающие программы.**

# 10. GRASP.PY — УНИВЕРСАЛЬНЫЙ ВЫБОР ЗАХВАТА

**Это центральный модуль всей системы.**

Функции:

```python
generate_grasps(object_state, scene)
check_grasp_clearance(candidate, scene)
solve_candidate_ik(candidate, robot_state)
rank_grasps(candidates)
choose_grasp(object_id)
```

## Алгоритм

Для выбранного предмета:

1. Получить геометрию и ориентацию.
2. Определить возможные поверхности контакта.
3. Сгенерировать кандидаты захвата.
4. Рассчитать раскрытие губок.
5. Рассчитать положение инструмента.
6. Рассчитать pre-grasp.
7. Проверить свободное пространство для пальцев.
8. Проверить IK.
9. Проверить столкновения всей руки.
10. Проверить возможность подъёма.
11. Оценить длину траектории.
12. Выбрать лучший допустимый кандидат.

## Для кубиков

Начни с захватов между противоположными боковыми гранями.

Проверяй:

- Ширину кубика.
- Максимальное раскрытие.
- Высоту пальцев.
- Расстояние до стола.
- Расстояние до стенок коробки.
- Соседние кубики.
- Возможность последующего подъёма.

**Недостаточно определить центр кубика и направить туда захват.**

Нужно найти геометрически допустимую конфигурацию всего захвата.

## Выбор кандидата

Используй последовательный отбор:

1. Геометрическая допустимость.
2. Достижимость.
3. Отсутствие запрещённых столкновений.
4. Возможность подъёма.
5. Запас по неопределённости положения.
6. Минимальная стоимость движения.

Не вводи множество произвольных весов без необходимости.

## Порядок планирования

### Вариант 1 — прямое движение

Если весь путь руки и предмета свободен, используй его.

### Вариант 2 — подъём и перенос

Рассчитай:

1. Безопасный подъём.
2. Высоту относительно препятствий.
3. Перенос.
4. Подход к месту установки.
5. Опускание.

Высота рассчитывается по геометрии сцены, а не задаётся одной чрезмерной константой для всех задач.

### Вариант 3 — RRTConnect

При сложных препятствиях используй OMPL RRTConnect в пространстве суставов.

Для каждого состояния и участка пути проверяй:

- Ограничения суставов.
- Геометрию звеньев.
- Геометрию пальцев.
- Геометрию переносимого предмета.
- Коробки и соседние объекты.
- Самостолкновения, если применимо.

Не заменяй проверку всей руки поиском пути только для центра захвата.

После планирования убирай лишние точки, сохраняя допустимость траектории.

```text
   ↓
Choose Best Grasp
   ↓
Plan Approach
   ↓
Visual Alignment
   ↓
Grasp
   ↓
Verify Holding
   ↓
Lift
   ↓
Plan Transfer
   ↓
Move
   ↓
Place
   ↓
Release
   ↓
Verify Placement
```

Это единый механизм для всех задач.

Укладка, сортировка и башни используют эту функцию, а не собственные реализации захвата.

## Проверка захвата

Используй доступные признаки:

- Фактическое раскрытие губок.
- Перемещение предмета вместе с рукой.
- Наличие предмета в захвате по камере.
- Состояние исходного места.

Не считай исчезновение объекта из кадра достаточным доказательством.
